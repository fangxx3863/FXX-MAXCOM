# ADR-0024: 粘底（自动滚动）的两条失效路径 —— 「视图不可见」与「单行续接」

- 状态：**accepted**
- 日期：2026-10-30
- 裁决人：项目负责人（缺陷报告：「有时候开了自动滚动，切标签页不会到底部，然后单行多数据也不到底部」）
- Supersedes：无
- 关联：ADR-0023（同属收发页渲染层：尺寸/可见性是一等事件）、ADR-0022（方向标记，同页）、SPEC `03-modules/logview`

## 背景

「自动滚动」勾选是收发页粘底的唯一权威状态（见 ADR-0023 同页既有状态机）：数据增长、程序性
`scrollToBottom`、分页装卸产生的 `scroll` 一律不改开关。这条纪律成立的前提是——
**「内容变高」这件事一定有人负责贴底**。修复前有两处没人负责，且都长在「看起来理所当然」的判断上。

### ① 视图不可见时，贴底只能算出 0

切标签页 / 切页面 / 浮窗收起走的是 `display:none`（`.session-ui.hidden-session`、`.page.hidden`）。
此时 `clientHeight` 与 `scrollHeight` 都是 **0**：

| 动作 | 隐藏态下的实际结果 |
|---|---|
| `append` → `scrollToBottom()` | `scrollTop = scrollHeight - clientHeight = 0`，写进去也不生效（没有布局盒） |
| `ensureWindow()` | `clientHeight === 0` 直接空转 |
| `fillChunk()` 实测高度 | `offsetHeight === 0`，被 `measured > 0` 守卫挡住 → 高度表停在估算值 |
| 浏览器对 `scrollTop` 的处理 | **冻结在隐藏前的旧值**，恢复可见后原样带出来 |

于是「勾着跟随 + 后台一直有数据」= 回来时 `scrollTop` 还是隐藏前那一位，而 `scrollHeight` 已经涨了
几屏。旧代码在恢复可见时只走 `ensureWindow()`（判据是「宽度没变」→ 不是尺寸变化），从不重贴底。

### ② 单行续接：一行都没新增，内容却在变高

设备不发换行、一直往同一行里灌数据时，`partial` 续行会在入队时合并进同一行（数据模型刻意如此：
时间戳只打一次）。这一行会折成几十上百个视觉行，**`rows` 一行都没涨**。而贴底的条件是
`appendedRows > 0` —— 纯续接批次恒为 0，于是内容在涨、视图纹丝不动，越落越远。

用户现场就是这条：`PT100: R_REF_P=...` 一整屏不换行的数据流，末尾那一行高到超出视口。

### 实测故障链（真实浏览器）

| 用例（`logview-stick-bottom-test`，修复前） | 断言 | 实测 |
|---|---|---|
| 单行续接 24 批（同一行折成 285px） | 仍贴底 | `scrollTop=6447` / `max=6713`；末行 `bottom=682` > 视口 `416` |
| 隐藏期到达 10 批 → 切回 | 切回贴底 | `scrollTop=7549` / `max=13078` |
| 隐藏期无数据 → 切回 | 切回仍贴底 | `scrollTop=7549` / `max=13078` |
| 隐藏期长行继续变长 → 切回 | 切回贴底 | `scrollTop=7549` / `max=13154` |

端到端（真实应用 + 演示后端，`logview-tabswitch-test`，修复前）：切页面回来 `scrollTop=163` /
`max=467`（末行 `bottom=715` > 视口 `415`）；切标签页回来 `scrollTop=923` / `max=1227`。

**这两条都必须「先停数据再断言」**：数据还在流时，下一条新行会让 `append` 顺手贴底，
把缺陷盖住 —— 用户说的「有时候」正是这个意思（数据一停、或者只剩续接，就露馅）。

## 决策

### 1. 「内容变高」的判据：新增行 **∨** 续接了 pending 行

```ts
if (this.autoscroll.checked && (appendedRows > 0 || mergedChunk >= 0)) this.scrollToBottom();
```

`mergedChunk` 是本次批次里发生过 partial 续接的行所在页（续接行恒为最后一行 → 即尾页，
且 `renderTail`/`fillChunk` 刚刚重渲染过它，高度确实变了）。贴底只在跟随态发生，
手动滚动态不受影响。

### 2. 可见性是一等事件：`resync()` + `ResizeObserver` 的「恢复」分支

| 通路 | 触发 | 作用 |
|---|---|---|
| `switchPage("logview")` / `SessionUI.onActivated()` | 用户点页签 / 点会话标签 | 同步调用 `logViewPage.resync()` |
| `ResizeObserver`（`onViewResize`） | 尺寸 0 → 非 0（`display:none` 恢复、换容器） | `resumed` 分支：按真实布局重测 |

两条都要，理由不同：

- `resync()` 是**确定性**入口。RO 的回调时机由浏览器调度，且各 WebView 对「元素从
  `display:none` 变回可见是否派发观察」并不一致（桌面端跑的是 WebKitGTK / WKWebView，
  与回归用的 Chromium 不同源）。用户点一下页签就该立刻落到底，不能押在观察器时序上。
- RO 是**兜底**入口。爆炸视图换容器、浮窗拉伸、侧栏开合等路径不会经过 `switchPage`，
  它们只改几何。

`onViewResize(force)` 的判据从「宽度变了才重算」扩成「宽度变了 **或** 刚从 0 尺寸恢复」：
隐藏期间什么都没测到，高度表里的值全是估算，和宽度变化一样必须整批作废重测。
另外 `w === 0 || h === 0`（仍不可见）时直接返回 —— 量不出任何东西，白测。

### 2b. `resync()` 必须**断言**「刚恢复」，不能**推断**（CI 暴露的第三条）

第一版 `resync()` 只是 `onViewResize(force)`，而 `resumed` 仍由 `lastW === 0` 推断 —— 于是它
继承了同一个隐含前提：**观察器一定看见过隐藏态**。这个前提不成立：

> `display:none` 期间主线程可能一直被占满（后台高频续接、整页重渲染）。此时浏览器**一帧都不跑**，
> `ResizeObserver` 会把「隐藏 0×0」与「恢复」合并成一次**净变化为零**的观测 —— 一次回调都不派发。

于是尺寸「看起来没变」，`resumed` 为假，`resync()` 直接返回，贴底当场丢失。macOS CI 上的失败
正是这一条（`logview-stick-bottom` 的「隐藏期间来数据」：`scrollTop=7587` 而 `max=13116`，
紧接着的下一条用例里才被补上）。

修法：`resync()` 先 `lastW = lastH = 0`，**自报「无有效测量」**再走重测 —— 可见性是调用方
断言的事实（`switchPage` / `onActivated` 知道用户刚点回来），不该由几何反推。
同时恢复路径补上「两轮收敛」：贴底会改变装载窗口（尾页进出），几何随之再变一次，
落点可能已不是底部（与 `scrollRowIntoView` / `alignRowToTop` 同一条纪律）。

### 3. 位置恢复：三态，而不是两态

| 状态 | 恢复方式 |
|---|---|
| `自动滚动` 勾选（跟随最新） | `scrollToBottom()` —— 落到**重测后**的真实底部 |
| 手动滚动态 **且** 此前有可测量位置 | `min(lastGoodScrollTop, maxScroll)` —— 还原阅读位置 |
| 手动滚动态 **且** 无可测量位置（首次可见） | `alignRowToTop(顶部第一行)`（沿用 ADR-0023 的锚点法） |

`lastGoodScrollTop` 只在 `clientHeight > 0` 时记录：隐藏期写入的 `scrollTop` 不生效、
隐藏期派发的 `scroll` 也不代表用户在看哪 —— 记了反而会把阅读位置污染成 0。

### 4. 不走「scroll 事件里判归因」的老路

最省事的写法是在 `scroll` 回调里发现「不在底部就解锁 / 在底部就贴底」。**不做**：内容增长本身
也会派发 `scroll`，归因歧义正是既有粘底状态机（ADR-0022/0023 同页注释）刻意避开的坑，
而且突发数据会把开关冲掉。本 ADR 的两条修复都只在**已知的因果点**上动作
（`append` 里知道"这一批续接了哪一行"；`resync`/RO 里知道"视图刚恢复"）。

## 后果

- 正面：
  - 切标签页 / 切页面 / 浮窗回来，勾着自动滚动就一定在最新一行；数据停了也一样。
  - 设备不换行的长行流（现场那种一整屏 `PT100: ...`）会持续跟随，不再越落越远。
  - 手动滚动态切回来不再被拽到底部，也不再被弹回顶部（浏览器不再替我们决定）。
  - 与 ADR-0023 合并成一条统一语义：**几何/可见性变化 = 重测 + 复位**。
- 负面 / 风险：
  - 恢复可见时多一次同步布局读（已挂载页数 × `offsetHeight`），与 ADR-0023 的宽度变化同量级。
  - 续接批次现在也会调一次 `scrollToBottom`（读 `scrollHeight`）：长行高频续接时每批多一次
    强制布局。实测演示后端与真实长行流下无感；如将来出现高频续接热点，可按帧合并。
  - `resync()` 会重测并可能改动 `scrollTop`，因此**只能在视图已可见后调用**（两处调用点都在
    `classList.toggle("hidden"/"hidden-session")` 之后）。
  - 因为 §2b 要「断言」而不是「推断」，`resync()` 一律走整批重测：点一下已激活的页签/标签也会
    付一次同步布局读（已挂载页数 × `offsetHeight`，不是行数）。实测无感，且换来的是不依赖观察器。
- 未纳入：
  - 不引入「记住每个标签页的滚动位置」这类多标签记忆（跨会话的阅读位置是另一个特性）。
  - 不为续接行单独做「行内折叠/截断」渲染（属于显示偏好，另案）。

## 回归锚点

- `app/scripts/logview-stick-bottom-test.mjs`（**真实浏览器** + 直接实例化 `LogViewPage`，
  esbuild 转译后注入页面，不依赖 dist）：新行贴底、单行续接变长、隐藏/恢复（有数据 / 无数据 /
  隐藏期继续变长 / **同一帧内隐藏+恢复**）、手动态不拽走、重新勾选即贴底。
  **试金石**：修复前 **8/14**（上表四项失败）→ 只修 ①② 后本地 14/14，但 macOS CI 上仍挂 2 条
  （§2b 的 RO 合并）→ 加上 §2b 后 **18/18**；把 `resync()` 的归零去掉可稳定复现那 2 条失败。
- 可见性用例的写法有两条硬要求，否则会在慢机器上假失败：
  - 每个可见性切换之后 `requestAnimationFrame` 等两帧（带超时兜底），让「隐藏态」真的被观察者
    看见一次 —— 真实用户也不可能在一帧里切走又切回；
  - 「纯 RO 兜底」那条先检查观察器是否真的派发过 0×0（`lastW/lastH === 0`），没派发就记为
    **跳过**而非失败：无头环境窗口不可见时整段不跑帧，这条兜底路径根本不存在，
    产品行为由 `resync` 覆盖。
- `app/scripts/logview-tabswitch-test.mjs`（**真实浏览器** + 真实应用 + 演示后端）：
  切页面 / 切标签页回来贴底、手动态位置守住、重新勾选贴底。
  **试金石**：修复前 **8/12**（`切页面回来 scrollTop=163 vs max=467`、`末行 bottom=715 > 415`、
  `切标签页 923 vs 1227` 四项失败），修复后 **12/12**。
- 为什么不能用 jsdom：缺陷本体是 `display:none` 下的滚动几何（`clientHeight`/`scrollHeight` 全 0、
  `scrollTop` 被冻结）与真实折行高度，jsdom 两样都不做（与 ADR-0022/0023 同一条教训）。
- 既有回归继续盯住相邻语义：`logview-sticky`（开关不被数据冲掉）、`logview-lazy`（装卸窗口）、
  `log-resize-test`（宽度变化作废高度缓存）、`find-jump-test`（跳转落点）。
