# ADR-0023: 收发区高度缓存必须随容器宽度失效 —— 尺寸变化是一等事件

- 状态：**accepted**
- 日期：2026-10-13
- 裁决人：项目负责人（缺陷报告：「在点开规则再关闭后，收发区什么都没有了；点进规则页面又能显示」）
- Supersedes：无
- 关联：ADR-0022（同属收发页渲染层）、SPEC `03-modules/logview`

## 背景

收发页的虚拟分页把 `#log-view` 按 `rowsPerPage` 切成 chunk，只挂载视口 ±`pageBuffer` 页；
远端页卸载成**空骨架**，靠 `min-height` 占位以稳住滚动高度。占位值取自 `chunkHeights[]`，
而它是**实测值**：容器 `offsetHeight`。

问题在于，**实测高度是「当时的容器宽度」的函数**：日志行是否折行取决于可用宽度，
一行折成两行就是两倍高。而容器宽度会变，且变的时候没有任何东西通知收发页：

| 宽度变化来源 | 是否触发滚动 | 是否触发数据到达 |
|---|---|---|
| 「多字符串」/「规则」侧栏开合（`#multistr-panel` / `#rules-panel`，各 360px） | 否 | 否（已连上却无新数据时） |
| 窗口缩放 / 全屏、WebView 缩放（`setZoom`）、浮窗拉伸、爆炸视图 tile 尺寸变化 | 否 | 否 |

三件事同时成立，缺陷就藏不住了：行数据没变（不会重渲染）、滚动位置没变（`overflow-anchor: none`
下浏览器不替我们修正）、也没有 resize 通路去重算 —— 于是**陈旧的实测高度被当成事实继续用**。

### 实测的故障链（真实浏览器，1280px 视口 / 每页 50 行）

| 步骤 | 现象 |
|---|---|
| ① 宽 1203px | 每页 950px（每行一行）；`maxScroll = 4786` |
| ② 开侧栏 → 240px | 长行折行，该页实测 **2071px**（写入 `chunkHeights`） |
| ③ 关侧栏 → 恢复 1203px | 真实高度回到 950px，但占位 `min-height` 仍是 2071px → `scrollHeight` 虚高 1824px |
| ④ 宽布局下翻一眼历史再回到最新 | 未挂载页重新挂载，`min-height` 用 2071px 撑起 → **视口内可见行 = 0** |

④ 的表现就是用户看到的「收发区一片空白」：`自动滚动`仍是勾选态、数据仍在到达（RX 计数在涨），
但贴底贴到的是被 `min-height` 撑出来的空隙里。点开侧栏后又"好了" —— 那只是因为宽度再变一次，
折行变多把空隙填满了，属于歪打正着，不是恢复。

## 决策

### 1. 观察容器自身尺寸，宽度变化即作废高度缓存

`LogViewPage` 在构造时对 `this.view` 挂 `ResizeObserver`（能力守卫：
jsdom 无此 API，测试与老环境自动跳过），回调里比对 `clientWidth` / `clientHeight`：

- **宽度变化** → 高度缓存整批作废并重算（下详）；
- **仅高度变化** → 只重排装载窗口（`ensureWindow`）—— 页高与宽度无关，缓存仍然有效，
  没有必要付出重测代价；
- 首帧（`lastW === 0`）只记录尺寸，不触发重算。

### 2. 作废＝重测已挂载页 + 按「每行平均高度」重估未挂载页

| 方案 | 取舍 |
|---|---|
| **重测已挂载 + 平均高度重估未挂载（选定）** | 未挂载页没有 DOM 内容可测，但它们与已挂载页是同一批数据的邻近片段，**每行平均高度**把折行算了进去 —— 这正是宽度变化的核心影响。误差只来自"某页恰好长行特别多"，且会在该页被挂载时立刻收敛到实测。 |
| 未挂载页回退到「行数 × 行高」 | 行高不含折行 → **系统性低估**。对长行日志（现场就是这样）页高可差 2 倍，`scrollHeight` 随之虚低，`scrollTop` 被浏览器钳制，表现为"往上翻跳不过去"。弃。 |
| 整窗重建（`rebuildChunks`） | 它会挂载全部页。对十万行是卡顿，且按滚动**比例**恢复位置在高度重估后必然偏移。弃。 |
| 不缓存，每次填充都实测 | 每次 `append` 都读全部已挂载行的布局 → 与"渲染成本恒定"这条既有设计目标直接冲突。弃。 |

测量前必须**先清掉所有容器的 `min-height`**：否则读到的还是上一个宽度撑出来的值 ——
自己污染自己的测量。

### 3. 位置恢复：跟随态贴新底部，否则锚回「视口顶部第一行」

- `自动滚动`勾选（用户在看最新）→ `scrollToBottom()`。修正后的底部是**真实**内容的底部。
- 否则以「视口顶部第一行」为锚点（未挂载的骨架没有行，跳过它 —— 它的位置正是待修的对象），
  重排后把该行贴回视口顶部。换算与 `scrollRowIntoView` 同源两条纪律：几何一律用
  `getBoundingClientRect`（与 `offsetParent` 无关）、赋完 `scrollTop` 再收敛一轮
  （挂载目标页会改变其上方各页的累计高度）。

## 后果

- 正面：
  - 侧栏开合、窗口缩放、浮窗拉伸、爆炸视图 tile 变化后，收发区几何都重新吻合，
    "数据在涨却什么都看不见"这类空白不再出现。
  - 未挂载页的估值从"行数 × 行高"升级为"新的每行平均高度"，折行多的会话里滚动高度更准。
  - popup 浮窗复用同一个 `LogViewPage`，一并受益。
- 负面 / 风险：
  - 宽度变化会强制一次同步布局读，成本是**已挂载页数**次 `offsetHeight`（不是行数）；
    真实浏览器实测 7 页场景下无感。
  - 布局抖动会带来连锁：出现竖向滚动条会使 `clientWidth` 少十几像素 → 再触发一次；
    第二轮宽度相同即 `return`，收敛。同理，字号随缩放变化时在**同一次**回调里先
    `refreshRowHeight()` 再测量，避免"按旧行高测新行高"。
  - `ResizeObserver` 无 `dispose` 出口：会话标签页被移除后观察随 DOM 脱离而不再触发，
    与既有页面对象同寿命，暂不引入销毁协议。
- 未纳入：
  - 不为宽度变化做响应式字号/列数调整（那是显示偏好，归设置页）；
  - 不把 `pageBuffer` / 重估策略暴露为设置项（没有用户可理解的取舍）。

## 回归锚点

- `app/scripts/log-resize-test.mjs`（**真实浏览器**，挂在 build 链 `find-jump` 之前）：
  变窄 → 变宽 → 翻历史 → 回到最新，断言可见行 > 0、`maxScroll` 回到初始值 ±5%；
  另含用户报的原始入口（真实点开/关闭「规则」面板）。
  **试金石**：同一份断言在修复前的产物上为 9/14（`回到最新后 0 行可见`、`关闭规则面板后 0 行可见`、
  `几何虚高 9384 vs 5717`），修复后 14/14。
- 为什么不能用 jsdom：缺陷本体是布局几何，jsdom 不做布局（`offsetHeight`/`scrollHeight` 恒为 0）
  且没有 `ResizeObserver`，桩出来的等宽等高几何根本挂不住这个缺陷（与 ADR-0022 同一条教训）。
- 既有分页回归（`logview-lazy` / `logview-sticky`）继续盯住装卸窗口与粘底语义，未被本次改动触碰。
