# ADR-0015: 数据流 — 单一原始流 + 各引擎独立后台解析

状态: accepted | 日期: 2026-07-31

## 背景
早期方案把时间戳分包放在数据管道前端，导致分包可能拦腰截断绘图二进制帧（设备发帧无间隙时），且"跳过1字节"若作用共享流会污染其他消费方数据。

## 决策
事件总线把**同一份原始字节流**扇出给每个消费方；各引擎（终端/日志/绘图/文件）在**独立的后台线程**里解析各自订阅的那份流。**解析互不耦合、互不阻塞、互不修改原始流。**

| 消费方 | 订阅 | 后台解析管线 | 产出 |
|---|---|---|---|
| 交互终端 | 原始流 | ANSI 状态机 → 屏幕缓冲 → SGR 染色（ANSI 时自动染色让位） | 屏幕网格 → 终端 Viewport |
| 传统收发 | 原始流 | 智能分包+时间戳 → 自动染色 → 过滤 | 日志行 → 日志 Viewport |
| 绘图 | 原始流 | 帧解析（本地游标对齐）→ 通道分离 → 环形缓冲 | 通道采样 → 波形/FFT/统计 |
| 文件落盘 | 原始流 | 智能分包+时间戳（与日志共用规则）→ 编码转换 | 原始数据+时间戳 → 文件 |

## 理由
- 各引擎各取所需，互不干扰；改动一个引擎不影响其他引擎，便于独立测试。
- 分包只作用于日志/文件路径，绘图永远拿到完整二进制帧。
- "跳过1字节"只推进绘图解析器本地游标，绝不影响其他消费方（见 03-modules/plot SPEC）。

## 后果
- 线程模型：I/O 线程 + 终端引擎线程 + 日志引擎线程 + 绘图引擎线程。
- 线程间通信：I/O→各引擎用 `queue.Queue`；各引擎→GUI 用**双缓冲 + 帧同步**（每 ~16ms 交换）；Compute Pool→GUI 用 `concurrent.futures` 回调。
- GIL 下 CPU 密集解析无法并行，3.13 吞吐足够；若高速串口暴露瓶颈再按需移 C 扩展。

## 附录：遗留待确认项（Open Items）
- **过滤行是否落盘**：倾向被过滤行默认**不写文件**，保留"落盘"选项。见 03-modules/logview tasks。
- **DPG 渲染 spike / 字体覆盖度 / DPG 维护状态**：见 ADR-0017。
- **终端回滚搜索**：倾向补充。
- **响应等待（P2 命令）范围**：冻结为"发送后读一次匹配"极简版。
- **插件系统 vs Python 脚本边界**：插件=传输/协议/可视化注册；脚本=用户级自动化。
